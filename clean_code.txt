RÈGLES DE PROGRAMMATION

1. Clarté et modifications de la base de données
- Si une exigence est ambiguë, peu claire ou comporte une zone d’ombre, arrête-toi et pose-moi toutes les questions nécessaires avant de poursuivre.
- Si une tâche implique une modification de la base de données, arrête-toi et présente-moi les changements envisagés. Nous en discutons. Après mon accord, tu peux modifier la base, puis reprendre la fonctionnalité en cours.

2. Backend et tests
- Le TDD est obligatoire pour le backend : comprendre la fonctionnalité et ses enjeux, puis préparer les tests avant de commencer à coder.
- Prévoir des cas positifs, négatifs, limites (boundary) et extrêmes (edge). Les tests unitaires doivent couvrir absolument tous les cas possibles et imaginables.
- N’écris jamais de tests unitaires après avoir écrit le code.
- Les tests unitaires sont prioritaires et restent obligatoires. Pour vérifier les fonctionnalités complexes, privilégie fortement les tests E2E en complément. À la fin des tests E2E, produis un résultat vérifiable et reproductible.
- Si un système doit être testé isolément, écris d’abord toutes les façons dont il pourrait échouer, puis écris le code.

3. UI/UX
- Fais preuve de créativité et privilégie les icônes aux textes verbeux.
- Limite la palette à une couleur principale et une couleur secondaire.
- N’utilise pas de dégradés multicolores.
- L’utilisateur doit comprendre le fonctionnement de l’application et de la page en la regardant.
- Évite les formulaires longs ; divise-les en étapes si nécessaire.
- Toute modification du frontend doit être responsive et s’adapter aux écrans.

4. Composants frontend
- Tous les composants doivent provenir de EGSA_ERP_Frontend/src/app/shared/ : utilise un composant existant ou, s’il n’existe pas, crée-le dans ce dossier puis utilise-le.
- Un composant peut être adapté aux besoins via des slots ou des props, mais il doit provenir du dossier shared.
- N’utilise jamais d’éléments div ou span ; utilise les composants partagés appropriés, comme ButtonComponent ou TitleComponent.

5. Pages et modules de référence
- Page de liste : prends comme référence la page qui affiche les factures.
- Modale d’ajout : prends comme référence la modale qui permet d’ajouter un aéroport.
- Page d’ajout : prends comme référence la page qui permet de créer une facture manuellement.
- Boîtes de confirmation, notifications toast, etc. : utilise le module Aéroport ou le module Bien comme seule source de vérité.
