# Tests : Modifier un contrat

Module          : Contrat (operation-service)
Page de départ  : http://localhost:4200/commercial/contract/<id>
Page testée     : http://localhost:4200/commercial/contract/<id>/modifier
Dernier passage : 2026-10-10, local, base de test
Résultat        : 10 PASS, 0 FAILED, 1 BLOQUÉ, 11 non testés

Statuts :
- PASS    : vérifié, conforme au résultat attendu.
- FAILED  : vérifié, non conforme. Détail obligatoire dans la section « Échecs ».
- BLOQUÉ  : impossible à exécuter. La raison va dans la colonne Observation.
- -       : pas encore testé.

Ce fichier ne contient que les vérifications manuelles : parcours à l'écran,
comportement réel de la base et des autres services. Ce qui se vérifie par un
test automatique est dans le code (voir .claude/rules/strategie-de-test.md).

Règle métier : seul le commercial modifie un contrat, et seulement aux statuts
BROUILLON, RENVOYE_AU_COMMERCIAL et REFUSE_PAR_CLIENT. La modification garde le
même contrat et son statut. Elle ne fait pas avancer le workflow.

## Pour rejouer les tests

1. Le compte utilisé ne doit pas avoir le rôle JURIDIQUE sur MOD_DC_CONTRAT
   (user_privilege_overrides.role_id). Le compte test l'avait (role_id 1008, ligne 8113) ;
   il a été retiré le 2026-10-10 pour ces tests. operation-service garde les privilèges
   en cache 15 minutes par jeton : se reconnecter après un changement de rôle.
2. Brouillon de test : 2026-10, id 54f4284c-ed1c-4cfd-842b-e9dcd5634683, créé par
   l'API à partir du contrat 2026-7 (1 bien tarifé, 1 prestation, 1 caution).
3. Contrôles en base : tables contrats, contrats_biens, contrats_services,
   contrats_cautions et contrats_rips de egsa_operation, filtrées sur contrat_id.
