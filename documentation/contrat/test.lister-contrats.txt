## Échecs

### E-1 : Message trompeur quand une recherche ne renvoie rien
- Étapes pour reproduire : aller sur /commercial/contract, saisir « xyzabc » dans la recherche.
- Résultat attendu : un message qui dit qu'aucun contrat ne correspond à la recherche.
- Résultat obtenu : « Aucun contrat » / « Aucun contrat n'est disponible pour le moment ».
- Gravité : mineur. Lié à une nouvelle anomalie (ANO-16).

### E-2 : Tiroir des filtres avancés vide (corrigé, ANO-17)
- Étapes pour reproduire : cliquer sur « Filtrer ».
- Résultat attendu : les 6 filtres (statut, type, client, aéroport, échéance, service) s'affichent.
- Résultat obtenu : le tiroir affiche son titre, « Aucun filtre actif », puis Réinitialiser et Terminer. Aucun champ.
- Cause constatée : `contrat-list-view.component.ts` déclare `<app-filter-drawer ... />` sans contenu. Les options des filtres existent dans la classe mais ne sont jamais rendues.
- Gravité : majeur. Les filtres avancés sont inutilisables. Lié à une nouvelle anomalie (ANO-17).

### E-3 : Tri Client / aéroport et Statut sans effet visible (non reproduit le 2026-10-10, voir ANO-18)
- Étapes pour reproduire : cliquer sur « Client / aéroport », puis sur « Statut ».
- Résultat attendu : l'ordre des lignes suit le tri demandé.
- Résultat obtenu : l'ordre ne change pas, ou ne correspond pas au tri. Côté API, `sort=clientRaisonSocialeSnapshot,asc` et `sort=statut,asc` renvoient bien des lignes triées. Le problème est donc côté affichage.
- Gravité : moyen. Lié à une nouvelle anomalie (ANO-18).

### E-4 : Tri par période de validité ignoré
- Étapes pour reproduire : cliquer sur « Période de validité ».
- Résultat attendu : les contrats sont triés par date d'expiration.
- Résultat obtenu : l'API renvoie `2027-12-31, 2028-02-29, 2028-06-30, 2027-12-31, 2029-04-30, 2028-12-31` pour `dateExpiration,asc`. Ce n'est pas trié, et le même ordre apparaît pour `desc`.
- Cause probable (à vérifier, non confirmée) : le tri SQL porte sur la colonne calculée `date_expiration`, alors que la valeur affichée vient de `ContratEntity.getDateExpiration()`, qui la recalcule.
- Gravité : moyen. Lié à une nouvelle anomalie (ANO-19).

### E-6 : Recherche « % » renvoie tous les contrats
- Étapes pour reproduire : saisir « % » dans la recherche.
- Résultat attendu : 0 ligne, le caractère est cherché tel quel.
- Résultat obtenu : les 6 contrats s'affichent, car `%` joue le rôle de joker SQL.
- Gravité : mineur. C'est ANO-08, toujours ouverte.

### E-5 : Sélection de la taille de page par clic sans effet
- Étapes pour reproduire : ouvrir le sélecteur « Rows per page », cliquer sur « 5 ».
- Résultat attendu : 5 lignes par page, pied « 1–5 sur 6 ».
- Résultat obtenu : la valeur reste à 10. Le même choix au clavier fonctionne.
- Gravité : mineur. À confirmer à la main, car l'outil de test peut mal cliquer sur une option de liste déroulante.
